# Enums

It is common for a field to only accept or provide a discrete and limited set of values. In these cases, it can be useful to use enumerations (generally abbreviated "enums") in order to clearly communicate what the set of allowed values are.

## Guidance

Enums **should** be used for values that change infrequently. For frequently changing values or open-ended sets, use `string` instead.

### Naming

- All enum values **must** use `UPPER_SNAKE_CASE`.
- Enums **should** include an explicit unspecified value as the first value, named `[ENUM_NAME]_UNSPECIFIED`. This allows safe default handling and clear distinction between "not set" and "set to a specific value".
  - An exception is if there is a clearly useful zero value. In particular, if an enum needs to represent `UNKNOWN`, it is usually clearer for it to be the zero value rather than having both `UNSPECIFIED` and `UNKNOWN`.

```yaml
BookFormat:
  type: string
  enum:
    - BOOK_FORMAT_UNSPECIFIED
    - HARDBACK
    - PAPERBACK
    - EBOOK
```

### When not to use enums

Enums **should not** be used for:

- **Frequently changing values** - Use `string` with `pattern` or `example` instead
- **Widely-adopted standards** - Use existing standard representations (ISO codes, BCP-47 language tags, IANA media types, etc.)
- **Boolean values** - Use `boolean` for simple true/false scenarios
- **Large or unbounded sets** - Use `string` with validation

### Documentation

Enums **must** include a `description` field explaining the purpose of the enum and whether it is frozen or open to future additions.

Enum values **should** be documented to explain exactly what each value represents. If two values are similar, differentiate them carefully. Clear documentation reduces customer support queries and prevents misuse.

```yaml
OrderStatus:
  type: string
  description: |
    Current status of the order. This enum is open and may include additional statuses.

    - ORDER_STATUS_UNSPECIFIED: Status not specified
    - PENDING: Awaiting payment confirmation
    - PROCESSING: Payment received, order being prepared for shipment
    - SHIPPED: Order dispatched and in transit to customer
    - DELIVERED: Successfully delivered to customer address
    - CANCELLED: Order cancelled by customer or merchant before shipment
  enum:
    - ORDER_STATUS_UNSPECIFIED
    - PENDING
    - PROCESSING
    - SHIPPED
    - DELIVERED
    - CANCELLED
```

## Rationale

Enums provide type safety and clear constraints, but at the cost of flexibility. The guidance to use enums sparingly prevents breaking changes when value sets grow or evolve. The unspecified value enables graceful handling of missing or unknown values without breaking existing clients.
