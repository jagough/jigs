# Methods

APIs are composed of methods that represent specific operations a service can perform. This document describes the types of methods and guidance for choosing between them.

## Guidance

When designing API operations, prefer methods in this order:

1. **Standard methods** (List, Get, Create, Update, Delete)
2. **Standard batch methods** (if operating on multiple resources)
3. **Custom methods** (when standard methods cannot express the operation)
4. **Streaming methods** (for real-time or long-running operations)

### Standard methods

Standard methods **should** be used whenever possible. They provide the most consistent and recognizable experience across different APIs and clients.

**Collection methods:**
- `List` - List resources in a collection
- `Create` - Create a new resource in a collection

**Resource methods:**
- `Get` - Retrieve a single resource
- `Update` - Modify an existing resource
- `Delete` - Remove a resource

Standard methods map to HTTP verbs:
- `GET` for List and Get
- `POST` for Create
- `PATCH` for Update
- `DELETE` for Delete

### Custom methods

Custom methods **should** be used only when standard methods cannot adequately express the required functionality.

Common scenarios for custom methods:
- Complex state transitions (e.g., `publish`, `archive`)
- Operations that don't fit CRUD patterns (e.g., `search`, `calculate`)
- Batch operations with special semantics (e.g., `import`, `export`)
- Resource lifecycle operations (e.g., `backup`, `restore`)

Custom methods **should**:
- Use HTTP `POST` as the verb
- Use clear, descriptive action names
- Be mounted on the relevant resource or collection

Example endpoints:
```
POST /v1/vendors/{vendor}/products/{product}:publish
POST /v1/vendors/{vendor}/products:import
POST /v1/orders/{order}:cancel
```

### Batch methods

When operating on multiple resources simultaneously, prefer standard batch methods over custom alternatives. Batch methods provide consistency while allowing bulk operations.

Common batch methods:
- `BatchGet` - Retrieve multiple resources by ID
- `BatchCreate` - Create multiple resources
- `BatchUpdate` - Update multiple resources
- `BatchDelete` - Delete multiple resources

## Rationale

Standard methods provide the most uniform experience across APIs because:
- **Automatable**: Tools can understand and generate code for standard patterns
- **Client compatibility**: Work consistently across CLI, UI, and SDK implementations
- **Predictable**: Users familiar with one API can quickly understand another
- **Tooling support**: Easier to build generic tooling and middleware

Custom methods sacrifice some consistency for expressiveness, but should still follow resource-oriented design principles when possible.
