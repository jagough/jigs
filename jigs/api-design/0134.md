# Standard Methods: Update

The Update method modifies an existing resource.

## Guidance

APIs **must** provide an Update method for resources that can be modified. The Update method modifies an existing resource and returns the updated resource.

### HTTP mapping

- HTTP verb: `PATCH` (preferred) or `PUT`
- URL pattern: `/v1/{resourceName}`
- Request body: The resource with updated fields

### Request

Update requests **must** include the resource name and the fields to update. The request **should** support partial updates using field masks.

**Field mask:**
A comma-separated list of field paths indicating which fields to update. If omitted, all writable fields are updated.

Example with field mask:
```
PATCH /v1/vendors/acme-corp/products/widget-42?update_mask=title,price
Content-Type: application/json

{
  "name": "vendors/acme-corp/products/widget-42",
  "title": "Super Widget v2",
  "price": 34.99
}
```

Example without field mask (full update):
```
PATCH /v1/vendors/acme-corp/products/widget-42
Content-Type: application/json

{
  "name": "vendors/acme-corp/products/widget-42",
  "title": "Super Widget v2",
  "price": 34.99,
  "description": "An even better widget"
}
```

### Response

The response **must** be the fully updated resource.

```yaml
# 200 OK
{
  "name": "vendors/acme-corp/products/widget-42",
  "title": "Super Widget v2",
  "price": 34.99,
  "description": "An even better widget",
  "create_time": "2024-01-15T10:30:00Z",
  "update_time": "2024-01-20T14:25:00Z"
}
```

### PATCH vs PUT

- **PATCH** (recommended): Allows partial updates with field masks
- **PUT**: Replaces the entire resource

APIs **should** use `PATCH` to support partial updates and reduce bandwidth.

### Create-or-update

APIs **may** support create-or-update behavior with an `allow_missing` parameter. When `allow_missing=true`, the server creates the resource if it doesn't exist.

```
PATCH /v1/vendors/acme-corp/products/widget-42?allow_missing=true
```

### Error responses

- `404 Not Found` - Resource does not exist
- `400 Bad Request` - Invalid update data or field mask
- `409 Conflict` - Concurrent modification (if using etags)
- `403 Forbidden` - Caller lacks permission to update the resource
