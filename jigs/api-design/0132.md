# Standard Methods: List

The List method retrieves a collection of resources.

## Guidance

APIs **must** provide a List method for resource collections. The List method returns multiple resources from a collection with support for pagination.

### HTTP mapping

- HTTP verb: `GET`
- URL pattern: `/v1/{parent}/{collection}`
- No request body

### Request

List requests **should** support pagination and **may** support filtering and ordering.

**Pagination parameters:**
- `page_size` - Maximum number of resources to return (default: 50, max: 1000)
- `page_token` - Token for retrieving the next page

**Optional parameters:**
- `filter` - Filter expression (see JIG-160)
- `order_by` - Comma-separated list of fields for sorting

Example:
```
GET /v1/vendors/acme-corp/products?page_size=25&order_by=title
```

### Response

The response **must** include:
- An array of resources
- A `next_page_token` for pagination (if more results exist)

The response **may** include:
- `total_size` - Total number of resources (if known)

```yaml
# 200 OK
{
  "products": [
    {
      "name": "vendors/acme-corp/products/widget-42",
      "title": "Super Widget",
      "price": 29.99
    },
    {
      "name": "vendors/acme-corp/products/gadget-99",
      "title": "Amazing Gadget",
      "price": 49.99
    }
  ],
  "next_page_token": "ChgKFGd0M..."
}
```

### Pagination

Clients retrieve subsequent pages by passing the `next_page_token` from the previous response:

```
GET /v1/vendors/acme-corp/products?page_size=25&page_token=ChgKFGd0M...
```

The server **may** return fewer resources than `page_size` requests. An empty `next_page_token` indicates no more results.

### Ordering

The `order_by` parameter **should** support:
- Comma-separated field names: `title,price`
- Descending order with `desc` suffix: `price desc`
- Default ordering is ascending

### Soft-deleted resources

List **should** exclude soft-deleted resources by default. APIs **may** provide a `show_deleted` boolean parameter to include them.
