# Standard Methods: Delete

The Delete method removes a resource from a collection.

## Guidance

APIs **must** provide a Delete method for resources that can be removed. The Delete method removes a resource and typically returns an empty response.

### HTTP mapping

- HTTP verb: `DELETE`
- URL pattern: `/v1/{resourceName}`
- No request body

### Request

Delete requests **must** include only the resource name in the URL path.

Example:
```
DELETE /v1/vendors/acme-corp/products/widget-42
```

### Response

The response **should** be empty with status `204 No Content` or return the deleted resource with status `200 OK`.

```yaml
# 204 No Content
(empty response)
```

Or:
```yaml
# 200 OK
{
  "name": "vendors/acme-corp/products/widget-42",
  "title": "Super Widget",
  "delete_time": "2024-01-20T15:30:00Z"
}
```

### Soft delete

APIs **may** implement soft delete, where resources are marked as deleted but not immediately removed. Soft-deleted resources:
- **Should** have a `delete_time` field
- **Should** be excluded from List operations by default
- **May** be permanently deleted after a retention period

See JIG-164 for comprehensive soft delete guidance.

### Cascading delete

When a resource has child resources, the API **should** fail the delete by default. APIs **may** support a `force` parameter to cascade delete:

```
DELETE /v1/vendors/acme-corp?force=true
```

This would delete the vendor and all its products.

### Error responses

- `404 Not Found` - Resource does not exist (or already deleted)
- `409 Conflict` - Resource has child resources and `force` was not specified
- `403 Forbidden` - Caller lacks permission to delete the resource

### Idempotency

Delete **must** be idempotent. Deleting a resource that doesn't exist (or is already deleted) **should** return `404 Not Found` rather than an error.
