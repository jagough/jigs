# JIG Numbering

JIGs are assigned unique numbers to enable clear referencing and organization. This document defines how JIG numbers are assigned and organized.

## Guidance

### Number assignment

JIG numbers **must** be unique integers starting from 1.

Authors **should** claim the next available number when creating a new JIG. If unsure which number to use, authors **may** temporarily use a placeholder and update it before finalizing the JIG.

### Number blocks

JIGs **should** be organized into the following number blocks:

- **1-99**: Meta-JIGs (process, governance, and JIG system documentation)
- **100-999**: General API design guidance
- **1000-1999**: Service architecture patterns
- **2000-9999**: Reserved for future use

Additional blocks **may** be defined as the scope expands.

### Category alignment

While JIGs are organized in category directories on disk (`/jigs/general/`, `/jigs/api-design/`, etc.), the number blocks provide an additional organizational layer.

JIGs **should** use numbers that align with their category:

- Meta-JIGs (category: `general`) **should** use numbers 1-99
- API design JIGs (category: `api-design`) **should** use numbers 100-999
- Service architecture JIGs (category: `service-architecture`) **should** use numbers 1000-1999

This alignment is a guideline to improve organization but is not strictly enforced. Authors **may** deviate when there is a clear reason (e.g., mnemonic numbering).

### Mnemonic numbering

In rare cases, JIG numbers **may** be chosen for mnemonic reasons rather than sequential assignment.

For example, JIG-404 might be used for guidance on HTTP 404 error handling, or JIG-2001 for guidance inspired by principles from the year 2001.

Mnemonic numbering **should** only be used when the connection is obvious and adds significant value to discoverability.

### File naming

JIG markdown files **must** be named using the four-digit zero-padded number corresponding to the JIG's `id` field.

For example:
- JIG-1 → `/jigs/general/0001.md`
- JIG-42 → `/jigs/api-design/0042.md`
- JIG-404 → `/jigs/api-design/0404.md`
- JIG-2001 → `/jigs/service-architecture/2001.md`

## Examples

### Sequential numbering

```markdown
# Typical sequence in /jigs/api-design/
0100.md  # JIG-100: First API design JIG
0101.md  # JIG-101: Second API design JIG
0102.md  # JIG-102: Third API design JIG
```

### Mnemonic numbering

```markdown
# Special cases
0404.md  # JIG-404: HTTP 404 Error Handling
0200.md  # JIG-200: HTTP 200 Success Responses
```

## Rationale

### Why number blocks matter

Number blocks provide a high-level organizational structure that complements the category directories. They enable:

- Quick identification of JIG scope by number alone
- Logical grouping of related guidance
- Room for future expansion without reorganization

### Why sequential assignment is preferred

Sequential numbering ensures:

- No gaps in the number space
- Predictable discovery (browsing by number)
- No conflicts when multiple JIGs are created concurrently

### Why mnemonic numbering is allowed

While sequential numbering is the default, occasional mnemonic numbering can:

- Improve memorability for commonly-referenced JIGs
- Create intuitive associations (e.g., HTTP status codes)
- Add value without disrupting the overall system
